# 记录的后台整理与完整编辑

用户提交「AI 帮我整理」后退出书写弹窗，列表展示尚未保存的整理候选；AI 准备完成后由用户主动进入整页编辑台，审核正文、标题、摘要、分类、标签、情绪和成长贡献。

确认时先持久化修改，再确认操作卡，一次确认即可。新策略候选（`indexPolicyVersion=1`）确认成功时记录已保存，已授权片段即可供 AI 按需查询；联想索引独立在后台处理。旧策略候选（version 0）保留原有等待全部记忆就绪的流程。失败仍可找回原文并处理；仅保存或未授权内容明确提示不可供 AI 查询。

新策略编辑台保留 AI 整理原有的记忆授权，并在每个片段内提供默认折叠的「参与联想检索」选择及简短原因，不增加必须确认的步骤。索引选择不改变 `memoryEnabled` 或 `todoEnabled`；明确的 `embeddingEnabled=false` 原样提交，缺失的旧字段按 true 处理。正文实际修改后将过期建议重置为 true，原因显示「正文已修改，默认保留检索」；之后再次手动关闭，以用户最后选择为准，修改标题、摘要或标签不会重置。

version1 已审核确认的 AI 来源正文保持只读，包括所有片段均未授权、memoryState=NONE 的情况；不能通过新增或编辑片段改写这份已确认正文。授权与成长仍使用各自已有控制，不随正文冻结被关闭。version0 和普通 record_only 记录沿用原编辑规则。

普通日常跳过索引后仍会保存、分类，日常内容仍可在对话中按需查询。这个说明仅适用于已确认并授权的内容，未授权片段会单独显示「不可供 AI 查询」。记录列表和详情分别展示保存/可查询状态与联想索引 pending、ready、failed 或主动跳过状态；`false + not_requested` 显示「已跳过联想索引」，不转圈、不显示失败或重试。新策略中索引失败不会将已保存记录改成仅保存，不影响已授权内容查询。列表与详情按实际 enabled/pending 片段继续轮询，pending 结束后停止，不把 READY 当作索引全部完成。

编辑台的确认提示、保存提示和片段详情仅对 version1 AI_ASSISTED 且有实际授权的内容说明确认后可按需查询；version0 保留后台加入记忆、完成后检索的提示，ONLY_SAVE 保留仅保存的提示。未授权片段在索引选项折叠时仍显示「未授权 · 不可供 AI 查询」。若部分片段仍在处理、另有片段已经失败，聚合状态同时列出处理中与失败数量。

聊天里的 record.create / record.organize 共用列表进度卡和同一编辑台，不再把完整表单挤进消息或书写弹窗。旧记录的「请求 AI 整理」同样返回列表。

候选来自 `GET /assistant/actions/records`，按登录用户隔离、包含跨会话任务；刷新、离开页面或关闭详情不会取消候选。只有「放弃这次整理」会取消。已修改但未保存的编辑内容在关闭时提示确认。

视觉延续 Blue hour：青色扫光标识整理、荧光黄表示待确认、分段轨迹表示后台记忆阶段；整页通过斜向展开、错位标题、旋转贴纸和纸页入场建立空间转换。减少动态效果偏好下关闭动画，保留全部状态和操作。

受控分支验收采用真实本地服务和桌面/手机浏览器流程，观察离开等待、刷新恢复、完整编辑、确认后后台处理、聊天候选恢复和取消行为；模型使用可控延迟的本地桩，不将其语义输出视为真实模型质量验证。指定真实代理的连续写日记、审核、索引与聊天查询补测结果统一见同级 B 仓 `docs/PROGRESS.md` 第 10 节。

浏览器验收脚本：`tests/browser/record-workflow-live.mjs`。仅用于本地隔离环境 `mirror-record-fixes-db` / `mu_mirror_test`（会创建合成账号、记录及聊天历史）；前端端口 5173、后端 9050。设置 `PLAYWRIGHT_MODULE` 为可用的 Playwright 模块位置，设置 `MIRROR_RECORD_WORKFLOW_OUTPUT` 为截图输出目录后通过 Node 执行。不运行该脚本连接正式服务。

选择性索引验收使用同一脚本，额外设置 `MIRROR_RECORD_INDEXING_ONLY=1`、`MIRROR_RECORD_TEST_DB_CONTAINER=mirror-record-selective-index-test-<隔离环境后缀>`，并确保 9050 后端只连接该隔离测试库，且测试环境新候选策略开关已开启。脚本检查显式命名的临时容器正在运行；它不会自动启动服务、切换数据库或开启后端策略。模型桩端口仍为 18080；`MIRROR_RECORD_EMBEDDING_FAILURE_BASE_URL` 必须指向可控的本机失败桩，缺失时失败场景明确报未完成。脚本覆盖全日常、混合授权/索引、刷新恢复、改正文后手动再选、后台索引失败，保存 1440px/390px 截图及脱敏请求/实际记录证据。新增脚本与 Node 测试不代表真实浏览器验收已经运行；本轮服务不可用时，以任务验证报告中的未完成项为准。

发布必须同时更新 Java 的列表接口与前端；数据库 `migration-v13-plan-to-todo.sql` 的备份、同步执行与回退说明位于后端 `docs/record-category-migration.md`，发布脚本已加入强制迁移步骤。

## 既有 version 0 本地验收结果

- 写日记提交后退出弹窗；列表显示实际 AI 准备状态和动画，刷新后候选仍可恢复。
- 完整编辑台修改正文、标题、摘要、分类、标签和情绪后，确认保存的实际记录保留修改。
- 确认后立即返回列表，模型桩延迟的记忆建立期间显示处理状态，完成后由带「已就绪」标签的正式记录替换。
- 390px 手机编辑台没有横向内容溢出；未改动退出后，刷新仍可继续审核。
- 使用真实后端会话历史恢复的聊天候选进入同一个编辑台；确认后返回记录列表。完成的聊天卡直接打开正式记录详情。
- 新账号不能通过候选列表读取其他账号的草稿；上述完整流程没有浏览器运行异常。
- 前端生产构建、后端编译、发布脚本 Bash 语法检查通过。本轮没有以大批单元测试替代交互验收。
