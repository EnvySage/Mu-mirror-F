# 成就完整目录与后端对照

核对日期：2026-11-11。本文按当前项目文件整理，供后续规则评审；本次不修改前后端运行逻辑或数据库。

## 当前范围

- 新版前端设计：12 套 × 8 枚 = 96 枚；支持镀层 24 枚；隐藏成就 2 枚（K-03、V-03）。
- 难度：★ 入门 41 枚；★★ 进阶 34 枚；★★★ 挑战 21 枚。难度与是否可镀层相互独立。
- 现有账号目录：34 枚；前端账号快照来自后端目录同步。新版 96 枚包含全部旧编号，新增 62 个编号，不是再增加 96 枚。
- 新版的获得/镀层状态为前端演示，不代表账号已获得；镀层挑战仍为设计草案，尚未接入后端。
- 镀层是同一枚章的进阶外观，不增加编号、成就总数或展示位；界面仅显示“可镀层”，不公开挑战条件。
- “隐藏成就”在获得前隐藏章面和普通条件；“隐藏镀层条件”是另一件事，适用于全部 24 枚可镀层章。

来源：`src/preview/achievementSets.js`（96 枚设计目录）、`src/preview/achievementCatalog.json`（34 枚账号快照）、`docs/achievement-sets-and-plating.md`（24 项镀层草案）。

## 接入后端前必须核对的差异

- `V-03`：旧版文案是资产搜索后打开文件（★）；新版是从对话检索找到并打开文件（★★）。旧客户端已从对话引用卡上报，但服务端只校验资产已归档与非空来源值，尚不能证明检索来源；需要补强验证并确认难度调整。
- `S-02`：旧文案统计已保存记录的记录类型；新版统计已确认记忆片段的内容类型。现有 SQL 本已统计 READY 且获批准的片段，因此主要是修正文案，不能误判为必须重做统计。
- `S-01`：旧文案是已确认记录的情绪；新版明确为已确认记忆片段的情绪。需要核对实际既有聚合口径。
- `C-03`：现有 SQL 已按 created_at 距今满 30 天判断（30 × 24 小时）；新版与此一致，不按用户指定的记录日期计算。
- `M-02`：新版难度由 ★★ 调整为 ★；“处理成功 / 索引完成 / 就绪”需要统一成同一个可验证成功状态。
- `D-03`：旧版描述历史会话至少有一轮对话，新版明确要求完整回复；现有服务端已经校验往日会话和非兜底 assistant 回复，新文案不等于新增规则。
- 其余多项旧编号调整了名称或措辞；应保留稳定编号和已获得事实，逐条审核后更新展示信息。
- `D-06` 与 `P-03` 当前普通条件均是确认 AI 行动提案并执行成功，属于跨章集重复奖励，需决定保留或调整。

## 统一实现时可复用的规则形态（建议，非已实现能力）

| 规则形态 | 示例 | 最小事实或口径 |
| --- | --- | --- |
| 首次成功 / 去重累计 | R-01、R-03、P-02、V-07 | 成功事件、用户、业务对象 ID，重试不重复计数 |
| 不同日期 / 周 / 月累计 | R-02、P-08、REF-08 | 明确的事件时间、上海时区、自然周/月，区分发生时间与业务归属日期 |
| 同一周期内达到次数 | R-04 及其镀层 | 同一天的不同记录数；普通阈值 3、镀层阈值 10 |
| 不同类型 / 对象覆盖 | K-04、G-06、S-01、T-08 | 词条、维度、类型、情绪、牌 ID 的集合及去重 |
| 多条件同时满足 | D-02、SYS-07、SYS-08 | AND 组合，以及各条件是否要求同会话、同对象、同周期 |
| 顺序 / 关联行为 | M-07、G-03、S-06 | 前后事件顺序、同一对象关联、来源信息；不能只累计点击数 |
| 时间间隔 / 历史窗口 | C-03、REF-06、REF-03 镀层 | 创建/生成时间、观察时间及间隔定义 |
| 连续周期 | R-02 镀层、S-08 镀层 | 连续日/月序列；和“不同日期累计”分开 |

尚待定义：有效对话、完整查看/已阅读、本人补充/校对、来源确已打开、单日多条内容是否有效、删除后是否保留累计、旧数据回填与规则版本迁移。新的查看类事实不能假设现有后端已能证明；后续必须逐项核对接口和业务落库点。
现有事实的复用限制：每日总结展开按日期永久去重，不能据此判断是否次日重开；资产打开按资产永久去重，不能据此统计跨日期打开；导出事件统一 subject='first'，不能据此区分 JSON 与 Markdown。需补充新的发生时间、来源关联或格式事实，保留现有幂等逻辑和旧进度。
所有普通/镀层规则均应以实际成功业务事实为准，失败、兜底回复、刷新、重复请求不应重复计入。
