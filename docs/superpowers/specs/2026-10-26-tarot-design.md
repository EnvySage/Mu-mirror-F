# Mirror 塔罗正式功能需求

日期：2026-10-26。状态：需求与开发计划阶段；没有实施业务代码。本文件覆盖旧的 `own/design/tarot-2026-10-26/design.md` 中冲突的建议，旧稿仅保留为第一轮视觉参考。

## 1. 目标与已确认范围

把塔罗做成 Mirror 日常记录之外的轻量体验：每日一次的仪式感、围绕一个问题的积极启发、逐日收集的美术收藏。保留蓝色舞台、剪影牌面、斜切标题、错落陈列和用户触发的翻牌放大，不做传统表单后台。

用户已确认：
- 首版使用现有 12 张原创牌面和 1 张牌背，后续补齐牌组。
- 每日运势每天随机一张，当天不可修改。
- 问一问每次只抽一张；问题选填，可结合个人资料生成 AI 分析。
- 只有每日运势解锁收藏。问题占卜即使抽到新牌也不解锁、不增加收藏计数。
- 收藏中未获得的牌显示牌背；已获得支持展览、放大。
- 每日牌只作为闲聊中的谈资，不抢现实问题的重点；解读积极，不羞辱用户或宣称命运决定结果。
- 用户希望探索可配置的资料范围：日记（可调整时间）、todo、镜子；下节为本轮提出的具体方案，不标成用户已经逐项批准。

## 2. 建议采用的首版默认值

这些是可评审的产品决策，不是仍留给开发者猜测的空项：

| 项目 | 建议规则 |
|---|---|
| 日期 | 服务器按 Asia/Shanghai，自然日 00:00 换日；未访问不补抽 |
| 抽取方式 | 主动点开抽取；12 张等概率、有放回；只用正位 |
| 每日文案 | 已审定的每牌积极牌义＋一个可选小行动，首版无需额外 AI 请求 |
| 问一问 | 可新开多次；每次牌一经确定不可改；补问题/重试解读不重抽 |
| 输入问题 | 0–500 个 Unicode 字符；留空只看通用启发，不猜测用户心事 |
| 默认资料 | 日记开启、最近 7 天；当前待办关闭；镜子关闭 |
| 日记窗口 | 7 / 30 / 90 天三档，含今天，以本次分析时刻为截止；不做自定义日期区间 |
| 待办 | 当前未完成项，不受日记天数限制；最多取 3 条相关项 |
| 镜子 | 按现有镜子首页选择口径，manual 优先、否则 monthly；仅接受 contextStatus=usable 的已生成快照；显示生成日期及归属月份，不自动生成/重建 |
| 保存配置 | 保存为账号偏好、跨设备同步；当前分析记录冻结本次实际配置 |
| 分析文案 | 目标 150–250 个中文字，以现实问题→牌义视角→小行动组织，不强制每篇机械分三段 |
| 历史 | 保存结果并支持按 ID/最近一次恢复；首版不做独立占卜历史列表、删除/导出管理页 |

配置面板默认收起，入口文案为「参考哪些内容」，收起时用一行说明当前配置。三个开关都关闭时仅结合问题与牌义。留空问题不主动读取个人资料；填写问题并点击「解读」后才按开关读取。新开一次清空当前问题，但保留账号偏好。

本轮不做逆位、三张牌阵、78 张全套、付费稀有度、每日连续签到奖励、AI 代抽、向聊天自动发送问题或分析、自动创建/修改待办。

## 3. 三个主流程

### 3.1 每日运势

进入 → 查询服务器今日日期/状态 → 未抽显示牌背与抽牌按钮 → 请求服务端抽取 → 结果持久化后翻牌 → 展示牌义与今日已锁定 → 若第一次得到该牌则解锁收藏。

- 唯一约束 `(user_id, draw_date)`；并发、双击、刷新、重试和多设备返回同一个记录。
- 抽牌落库和收藏计数在一个事务中完成。只有实际新插入的每日记录才增加一次计数；重复网络请求不累计。
- 跨日重试同一个 clientRequestId 返回原来的抽取及其 drawDate；前端显示「这是昨日抽取结果」，重新查询今天，须新的主动操作才能抽今天，不能自动补第二张。
- 网络断开时先按 requestId 恢复，再查询今日状态；禁止客户端预先显示自选随机牌。
- 同一天收藏已解锁牌仍可能再次抽到。重复牌增加「每日遇见次数」，不增加已解锁种类。
- 北京时间零点、页面恢复和账号变化重新查询服务器状态；本地时钟不决定抽牌资格。

### 3.2 问一问

默念/选填问题 → 抽一张 → 显示固定基础牌义 → 可填写或修改问题 → 展开/调整参考资料 → 解读 → 展示分析及真实来源。

- 抽牌是等概率随机，不根据问题、日记或收藏缺牌选牌。
- 问题牌不改变每日牌，也不进入聊天背景。
- 改问题或参考配置会创建新的分析版本，牌不变；不自动请求 AI，必须点击解读。
- 同一次分析进行中锁定重复提交；重新提交相同 requestId 返回同一分析，不二次扣用模型。相同 requestId 携带不同问题/配置返回冲突。
- 分析异步生成，页面显示生成状态，刷新可恢复；失败只重试分析，不重抽牌。
- 首版保存卡牌与最新分析结果；老分析仅用于幂等与状态核对，不提供版本比较界面。
- 无 AI 配置或服务不可用：基础牌义、每日抽取和收藏仍可用；显示可重试的真实原因，不把固定文案伪装成 AI 分析。

### 3.3 收藏册

展示实际启用牌组（首版 12 张），未获得位置只有牌背/「尚未相遇」。通过每日抽牌解锁，显示首次获得日期和每日遇见次数。点开进入鉴赏层，支持大图、前后切换、缩放、Escape 关闭、焦点返回。左右翻牌只遍历已解锁牌。

问一问可展示抽到但未收藏的牌；此时标「尚未收入收藏，等待每日相遇」，不提供手动收藏按钮。第一轮设计稿的「查看全部美术」入口不能带入正式产品。

后续添加牌面保留稳定 cardId 和旧记录；分母根据启用牌组更新。隐藏/停用卡不删除已拥有资产。锁定是收集体验，不承诺静态图片地址是保密资源。

## 4. 个性化资料与证据

Java 后端依据当前登录用户读取资料，前端只提交开关与时间，不上传任意原文让服务器信任。Python 本功能只接收有界材料并生成分析，不直接执行写工具。

- 日记：仅 source=user、未删除、done、record_memory_is_complete(recordId) 且 chunk.ai_memory_approved 的片段；排除 vault、系统总结和未获准内容。最多 4 条、每条最多 500 字符，窗口在 SQL 层生效，再按问题相关度排序。同一记录去重；没有匹配就不引用。嵌入服务不可用可降级关键词匹配，必须标记降级。
- 待办：仅本人、未删除、not_started/in_progress；direct 来源取标题/备注，record 来源还需原记录归属/删除状态及 todo_approved 合格。最多 3 条，每条 300 字符；不把状态转换回日记旧 metadata。该开关只允许本次参考，不触发执行。
- 镜子：最多 1 份、最多 1000 字符；只读现有可用快照，保留 snapshotId、versionNo、生成日期、periodMonth。它是模型总结而非新增事实；不符合 usable 则本次跳过并说明。
- 来源统一为 `kind=diary|todo|mirror`、sourceId、标题、日期、可用短摘录和版本指纹；仅显示分析确实引用的条目，支持打开原记录/待办/快照。
- 各开关真正控制检索调用。日记关闭不能经「镜子」偷偷查询原始日记；镜子自身可能概括日记，应在开关说明中写清。
- 生成前后校验资料仍可用。保存/读取分析时如引用来源已删除、撤销授权、待办状态/内容改变、镜子变 archive_only，旧分析标 stale，隐藏旧正文和摘录，允许用当前资料重解；保留抽牌结果和收藏。
- 问题/日记/待办/镜子文本都是数据，不执行其中的提示词指令。分析不写入 records、长期记忆、成长分数或画像。

## 5. 聊天里的每日牌

复用现有 `AssistantContext.divination`，只装当天已抽日牌；不主动抽牌，不装问题占卜、不装旧日牌、不装用户随口声称抽到的牌。

场景规则：
- 明确问自己的日牌：说明当前记录；还没抽时提示去抽，不编造。
- 自然相关的闲聊：可在现实回应后附至多一句温和比喻；同一会话同一自然日最多提供一次主动引用机会。为了避免过度提牌，机会被提供但模型没有使用时也不补发。
- 问代码、查资料、安排任务、执行写操作：不注入日牌内容。混合意图优先解决实际任务。
- 表达「别再提塔罗」：会话级关闭主动提及；明确「可以再提」恢复。明确询问仍可答；默认保守，不从引用文本或用户文档读取这些命令。
- 「愚者」理解为愿意开始、探索；不能说「不去做才是傻子」。乐观不等于保证成功、否定痛苦或替用户作决定。

隔离要求：牌义只用于最终自然语言回答，不进入规划工具、画像生成、记忆提取、分类或日记检索 query。旧聊天（loop 开/关）和 graph_v2 都需覆盖。未能可靠判断闲聊时不主动提及；首版保守规则不追求全意图分类。

## 6. 交互与集成

- 正式路由 `/tarot`，日牌/问一问/收藏使用页面内三个页签，支持 query 恢复 readingId。
- 桌面 AppSidebar 加塔罗入口；手机保留现有五槽底栏，在镜子页提供可见的「今日塔罗」入口，塔罗页有返回镜子动作。日牌摘要只在塔罗入口上展示，不在每条聊天旁挂牌。
- 路由必须同时登记在 router/index.js 和 router/presentationPages.js，补 MainLayout 标题与转场标识；避免有路由但渲染为空。
- 抽牌动画在服务端成功后触发，减少动态效果时直接切换。大图弹层复用焦点约束；切页/退出取消动画与轮询。
- 所有请求按账户归属清缓存与丢弃过期响应；前端 API 继续使用 camelCase 入参、拦截器转换后的 snake_case 响应，不用 localStorage 作为抽牌或收藏真相。

## 7. 完成标准

三仓真实联通并持久化后才算功能完成。浏览器假数据和静态设计稿不能替代以下验收：

1. 同日两设备并发只能有一张日牌；同 requestId 跨日重试不新增第二张；新日新操作可抽。
2. 重试不重复增加收藏，问题占卜永远不解锁收藏；退出/切号不串数据。
3. 三类资料开关与日记时间窗正确；没有资料能正常分析；来源失效后不再泄露旧摘录。
4. AI 失败/重启/刷新能恢复明确状态，不重抽、不无限转圈；模型真实调用与固定牌义有明确区分。
5. legacy loop 开/关及 graph_v2 均满足闲聊分寸，任务/工具/画像路径不带牌义。
6. 375 / 768 / 1440 像素宽度可用，无页面横向溢出；键盘鉴赏、减少动态效果、移动端入口都可用。
7. 保留现有记录、待办、镜子、聊天行为；协议、迁移和 AI upload 镜像对齐。
