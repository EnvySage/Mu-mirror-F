# Mirror Tarot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 本轮只编写计划；下文的命令、迁移与提交均尚未执行。

**Goal:** 在 Mirror 正式项目中交付每日固定日牌、可配置个人资料的单张 AI 问答，以及仅由日牌解锁的收藏册。

**Architecture:** Vue 负责交互；Java 是抽牌、收藏、账号配置、资料授权与分析任务的唯一持久化入口；Python 通过专用 gRPC 生成分析。聊天复用已有 DivinationContext，但仅允许进入最终回答。先交付数据库与抽牌闭环，再接资料和 AI，最后整合聊天与正式 UI。

**Tech Stack:** 现有 Vue 3 / Pinia / GSAP / Vite、Java 17 / Spring Boot / MyBatis / PostgreSQL、Python / gRPC 与现有 LLM 适配器；不新增 UI 库、任务队列服务或模型供应商。

**Spec:** [2026-10-26-tarot-design.md](../specs/2026-10-26-tarot-design.md)。其第 1 节是用户已确认范围，第 2 节是本轮建议默认值；执行前连同本计划一并评审。

## Global Constraints

- 首版使用现有 12 张原创牌面和 1 张牌背，后续补齐牌组。
- 只有每日运势解锁收藏。问题占卜即使抽到新牌也不解锁、不增加收藏计数。
- 服务器按 Asia/Shanghai，自然日 00:00 换日；未访问不补抽。
- 主动点开抽取；12 张等概率、有放回；只用正位。
- 默认资料：日记开启、最近 7 天；当前待办关闭；镜子关闭。
- 日记窗口：7 / 30 / 90 天三档，含今天，以本次分析时刻为截止；不做自定义日期区间。
- 问题 0–500 个 Unicode 字符；留空不读个人资料。AI 分析目标 150–250 个中文字，不编造证据。
- 每日牌只作为闲聊中的谈资，不抢现实问题的重点；解读积极，不羞辱用户或宣称命运决定结果。
- 分析不写入 records、长期记忆、成长分数或画像，不执行待办修改工具。
- 正式产品不带美术评审的全牌解锁入口，不把 localStorage 作为抽牌/收藏真相。
- 本计划中的文件名为新增建议；已存在的入口按实查路径列出。三个 Git 仓分别提交；不把另一仓的代码混入当前仓提交。

## Review Focus

1. 同 requestId 跨零点重试：返回原日期的牌，不能静默抽今天；Task 2/7 必测。
2. 问题抽到未收藏牌：可以看问答结果，但收藏仍锁定；Task 2/7 必测。
3. 关闭日记但开启镜子：只读可用快照，不穿透读取其原始日记；Task 3 必测。
4. 生成期间来源撤回/待办变更/快照失效：不发布旧分析，牌和收藏保留；Task 3/5 必测。
5. legacy 默认 loop 开启会跳过 ExtractIntent：聊天策略不能只挂在 ExtractIntent，规划/画像不能夹带牌义；Task 6 必测。

## 共享契约（Task 1 冻结，后续任务使用）

### HTTP

沿用后端 context-path=/api、`R<T>{code,message,data,timestamp}` 和 JWT；Controller 的 RequestMapping 写 `/tarot`，不要重复 `/api`。用户身份从服务端认证读取，不接受 body.userId。成功业务码仍为 200；分析受理用 data.status 表示，不另造 incompatible envelope。

| 方法/路径（均以 /api/tarot 开头） | 入参 | 返回 data |
|---|---|---|
| GET /cards | 无 | catalogVersion, activeCount, cards：id/ordinal/name/en/keyword/meaning/action/imageUrl/backUrl/active |
| GET /daily | 无 | serverDate, timezone, nextResetAt, draw 或 null |
| POST /daily/draw | clientRequestId: UUID | 同 daily，加实际 draw.drawDate、isNewDraw、newlyCollected |
| GET /daily/requests/{clientRequestId} | UUID | 已成功接受的原日牌；不存在返回 404，不触发抽取 |
| POST /readings | clientRequestId: UUID | readingId, cardId, createdAt, latestAnalysis 或 null；不接受 client cardId |
| GET /readings/{readingId} | UUID | 自己的 reading 和最新 analysis 状态 |
| GET /readings/latest | 无 | 最近一次 reading 或 null；静态路径不与 ID 路径混淆 |
| POST /readings/{readingId}/analyses | clientRequestId, question, options | analysisId, status, pollAfterMs=2000；默认设置由前端明确发送，后台保存快照 |
| GET /analyses/{analysisId} | UUID | analysisId, readingId, status, text, sources, notices, options, errorCode；非 completed 不返回旧 text |
| GET /collection | 无 | activeCount, unlockedCount, entries：cardId/firstObtainedAt/dailyDrawCount；未收藏无伪造 obtained 日期 |
| GET /preferences | 无 | diaryEnabled, diaryDays, todosEnabled, mirrorEnabled, version |
| PUT /preferences | 同上，expectedVersion | 新偏好和 version；版本冲突返回 409，不覆盖另一设备修改 |

`options = {diaryEnabled:boolean, diaryDays:7|30|90, todosEnabled:boolean, mirrorEnabled:boolean}`。
同 idempotency key 不同 payload 返回 409；无权限与不存在统一 404；参数错误 400；同 reading 有运行中分析时返回 409 并提供自己的 activeAnalysisId；系统拥塞返回可重试错误。
上述错误遵循现有 R 业务码约定，HTTP 状态行为沿用全局异常处理。前端送 camelCase、读拦截器转换后的 snake_case，normalizeTarot* 在一处做解析。

`source = {kind:diary|todo|mirror, sourceId:string, title:string, date:string, excerpt:string, version:string}`；不依赖模型提供链接，服务器按来源 ID 构建目标。分析输出引用标记 `[D1] / [T1] / [M1]`，仅返回被实际引用且重新验证合格的来源。

迁移建议 `B/src/main/resources/db/migration-v12-tarot.sql`；执行前重新检查编号，如已有 v12 则顺延并更新所有引用。同步 fresh-install schema.sql。不在计划阶段运行迁移。

| 表 | 必要字段/约束 |
|---|---|
| tarot_daily_draw | UUID id、user_id FK、draw_date、card_id、catalog_version、client_request_id、created_at；UNIQUE(user_id,draw_date)、UNIQUE(user_id,client_request_id) |
| tarot_daily_request | user_id、client_request_id、draw_id；PRIMARY KEY(user_id,client_request_id)，复合 FK 保证 draw 属于同一用户；记录包括并发失败者在内的所有成功返回请求与日牌的映射 |
| tarot_reading | UUID id、user_id FK、card_id、catalog_version、client_request_id、created_at、latest_analysis_id；UNIQUE(user_id,client_request_id) |
| tarot_analysis | UUID id、reading_id、user_id、client_request_id、payload_hash、question、options JSONB、status、text、source_refs JSONB、notices JSONB、error_code、created_at/started_at/completed_at/expires_at；UNIQUE(user_id,client_request_id)，同 reading 只允许一个 pending/running 的部分唯一索引 |
| tarot_collection | user_id、card_id、first_obtained_at、daily_draw_count；PRIMARY KEY(user_id,card_id)，count > 0 |
| tarot_preferences | user_id PK/FK、四项配置、version、updated_at；days CHECK IN (7,30,90) |
| tarot_chat_state | user_id、session_id FK、suppressed、last_offered_date、last_offered_run_id；PRIMARY KEY(user_id,session_id)，随会话删除清理 |

读写均限定 user_id；reading/analysis 用复合归属约束或等价事务检查避免错配。用户删除按已有用户清理模式级联，不新增账户管理业务。source_refs 只保存可核验 ID/版本/引用编号，不长期冗余存整个源文本。卡牌目录以版本化 JSON 为唯一内容源，历史 ID 永不复用。
